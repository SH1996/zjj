# 竹间记 · 慢慢来

> 不急 · 想起什么就写一句

一个纯前端、零依赖的单页笔记应用：随手记录、待办与提醒、店铺送货清单（含拍照识别）、接龙拆单、AI 语音整理、老铁有话说、数彩实验室、手机推送、GitHub 私有仓库同步、时光机与周回顾。以 PWA 方式添加到主屏幕后可离线打开。数彩实验室只做三件数学上成立的事：估冷门度（中了少分钱）、算覆盖设计（圈中兜下限）、做显著性体检（承认没优势）。

线上地址：https://sh1996.github.io/zjj/

## 数据存在哪里

- **默认全部在本机**：笔记保存在浏览器 `localStorage`（键 `bamboo.v11.*`），不上传任何服务器。
- 「老铁有话说」写出来的段子单独存在 `bamboo.v11.laoyou`，只在本机、不参与同步与备份，
  最多保留 40 条；点「存进笔记」才会变成真正的笔记。
- 接龙核单里「教它」、以及「AI 资料库」页手写的规矩，都存在 `bamboo.v11.jielong.memory`；
  接龙价格本在 `bamboo.v11.jielong.price`。两者都只在本机、不参与同步与备份，
  进「AI 资料库」可逐条查看与删除。拆单、核对、排箱三处 AI 动作之前都会先读这本。
- **可选云端同步**：在「设置 → GitHub 同步配置」填入私有仓库与访问令牌后，笔记会同步到该仓库的 `notes.json`。同步目标必须是**私有仓库**；程序在写入前会校验 `private` 字段，公开仓库会被阻止写入。
- 云端同步使用墓碑并集 + `updatedAt` 新者胜做冲突合并，时光机可查看并恢复任意历史版本。
- 「导出本地备份」会下载包含笔记、墓碑与操作日志的完整快照（schema 2）；导入会覆盖当前数据，覆盖前会自动再下载一份当前快照。

## 配置说明

| 配置 | 用途 |
|---|---|
| AI 接口地址 / 密钥 / 模型 | 兼容 OpenAI 格式（如 DeepSeek），用于 AI 提炼、竹语、老铁有话说、本周回顾、数彩实验室交叉解读 |
| 视觉模型 (Vision Model) | 拍照识别送货单用的多模态模型，默认 `deepseek-flash`；与文本模型分开配置 |
| 手机推送 Webhook URL | Bark 推送地址，页面关闭后仍可收到提醒 |
| 仓库所有者 / 名称 / 路径 / 分支 / 令牌 | GitHub 同步，仅用于你自己的私有仓库 |

### 安全须知（重要）

1. **只使用最小权限的细粒度令牌**：同步只需要目标私有仓库的 Contents 读写权限。切勿填入账户级经典 PAT（含 `delete_repo`、`admin:org` 等权限的令牌）。
2. **API 密钥与访问令牌以明文保存在本机浏览器的 `localStorage`**。设置面板不会回显已保存的凭据（留空表示不修改）；请勿在公用设备上保存高权限凭据，离开时可用「断开配置」清除。
3. 启用 AI 后，相关笔记内容会发送到你填写的模型服务；**已删除的笔记不会外发**。「老铁有话说」在新闻体与冷知识两种说法下会联网检索，其余说法不联网；「拍照识别」会把送货单照片发往视觉模型，照片只在内存中压缩处理，不写入 `localStorage`、不进入备份与云端同步。「数彩实验室」仅在你点击 AI 解读后发送统计摘要与候选，不发送笔记、凭据或完整历史数据。Bark 推送的正文会按 URL 编码后的长度截断，避免中文长笔记把推送 URL 撑得过长。
4. `.gitignore` 已排除 `notes.json`、`*.txt` 等，避免把真实笔记提交进公开仓库。

### 提醒的局限

提醒依赖页面在前台运行（15 秒轮询 + 浏览器通知）。页面被关闭或系统冻结后台时不会触发；需要离线提醒请配置 Bark。浏览器通知权限需由用户点击后授予。

## 项目结构

```
index.html      笔记主应用与全部界面样式（原生 JS，无构建步骤）
lottery-data.js 发布时从官网读取并校验的双色球 120 期 / 大乐透 100 期真实历史数据
lottery.js      数彩实验室：数据校验、统计算法、候选生成、回测与独立全屏界面
jielong.js      接龙拆单：解析、楼栋归一、装箱、价格本、AI 兜底、送达凭证合成
manifest.json   PWA 清单
sw.js           Service Worker：页面网络优先、静态资源缓存优先，API 请求直连不缓存
icons/          应用图标（含 maskable）
```

改 `index.html` 后直接推送到 `main`，GitHub Pages 会自动部署。**发布新版本时请同步更新 `sw.js` 里的 `CACHE` 名称**，否则旧缓存不会失效。页面版本由 `index.html` 顶部的 `APP_VERSION` 常量维护；`localStorage` 键名沿用 `v11` 不变，不要改名，否则用户数据会丢失。

### v15.14.0（2026-11-10）

两件事：把「教它」升级成一份真正会前置生效的 AI 资料库；装箱多了冬天保温的「一栋一箱」。

**一、AI 资料库（前置笔记本）**

以前教过的话只在核单那一步用得上。现在变成一本在接龙页任何 AI 动作之前都先翻的笔记本：

1. **三处 AI 全读它**：拆单提示词【老板交代过的】、核对提示词【老板教过的规矩】、排箱提示词【老板交代过的装箱规矩】；连「把一段话收成一句规矩」那一步也把已有规矩摊给 AI 看，避免记重、记反。
2. **自己也能写**：资料库页有「＋ 自己写一条规矩」，分人／货／钱／箱／其他五类。写的时候实时显示「只管「王姐」」——认不出对象就直接标红「对谁都算，慎用」，防止一句「谁不写楼栋都不算事」把所有人的疑点都放过去。
3. **看得见成效**：问题页顶部核对条会写「读了你 N 条规矩」「按你的规矩滤掉 N 条」；首页底部常驻一张资料库卡片，显示条数与最近记的一条；详情页问题页底部也能一键进去。
4. **按人／货／钱／箱分组**，每条标着「不算问题／要留意／单独一箱」、原话、记的日期，点「删」立刻恢复原样。全在本机 `bamboo.v11.jielong.memory`，不参与同步备份。

**二、装箱保温：一箱一栋**

冬天有些楼栋单量大，混装那箱一开一关，暖就跑了。装箱页新增一个开关：

- **最多三箱，每箱只装一栋**，按件数从多到少发（件数一样看单数），件数最多的先拿箱。
- 剩下没分到箱子的楼栋，明确列出来「装保温袋，或者回头再跑一趟」，不会悄悄消失。
- 某栋件数超过一箱上限时直接标红「这栋 X 件，得再带一个袋子」。
- 没写楼栋的单一律排到最后——都不知道往哪送，占一箱没意义。
- 哪栋以后都得单独一箱，点一下「X栋＋」就记进资料库，往后每次排箱先给它留一个。
- 保温模式下不调 AI 排箱（一箱一栋是硬规矩，混装方案用不上），也不受「自动/2 箱/3 箱」影响时仍可用「只带了两个箱子」限制箱数。
- 开关状态记在设置里，冬天打开一次，往后一直是这个模式。

### v15.13.1（2026-11-10）

### v15.8.0（2026-11-10）

楼栋 / 装箱 / 金额 / 送达 后面多了一栏「问题」：把这一单里要回头核的地方列成清单。

1. **只挑本地算得出来的**，不猜：名字、楼栋、商品、数量、单价、总价对不对得上。
2. **给少了**：原文单价明显低于平时（差 ≥ ¥1），按件数算出差额，红条排最前面。比如「三个酱肉包 6 元」而平时 2.5 一个 → 「「酱肉包」比平时少 ¥1.50，这次 ¥2/份，之前 ¥2.50/份」。
3. **账对不上**：原文写了总价，又写了逐样单价，两边差 ≥ 0.5 元 → 「少给了 ¥1」「多给了 ¥2」。合计差额写在顶上：「少收 ¥1.50」。
4. 其余几类：没写名字、没写楼栋、楼栋是按历史补的（只提醒不算错）、没定价（写清哪样没价）、单价 0 或高得离谱（房号被当成钱）、件数 0 或一件超 15、同一个人下了两单（只提一次）。

6. tab 上带数字角标，一眼看见有几条；全干净时显示绿底「没查出问题，N 单都对得上」，
   全被忽略时说「都标成「不用管」了」，不谎报都对得上。
7. **顺手挖出一个藏得深的 bug**：以前学来的价会被本单自己覆盖。张三写「三个酱肉包 6 元」，
   价格本里 ¥2.5 当场被改成 ¥2，「比平时少」就永远查不出来——线上实测就是这么漏的。

### v15.5.0（2026-11-10）

修两个"东西不见了"的毛病：楼栋有时认不出，包子有时整样漏掉。这两个都不该靠运气——不是词表里有才认，而是按规则推得出来。

1. **不认识的包子也认得**：以前靠一张商品词表，词表里没写「三鲜包」「粉丝包」「萝卜丝包」，这一行就整行当标题扔掉，人跟单一起消失。现在加了一层后缀扩展——凡是「…包 / …馒头 / …饼 / …粥 / …脑 / …饺 / …浆」结尾的中文串，从尾字往左吞并，遇到数量词、标点、数字就停，最长的那个就是商品。所以不管你写什么包子，只要带个「包」就不会丢单。

5. **日期行不会再变成订单**：`11.10 早饭接龙` 以前被读成第 11 单、金额 10 元；现在日期开头、又没楼栋没商品的行直接跳过。

- 所以它跟笔记一样：参与 GitHub 同步、进导出备份、能删能改、能搜索。首页分类新增「接龙」一栏，计数实时更新。
- 老记录的结构化数据坏了（比如手改了正文），打开时会拿正文重新拆一遍，不会白屏。

**边界**

- 拆单、算钱、装箱都在本机算，不联网。
- AI 只在主动点「用 AI 读」时参与拆单，改不了价格口径，也不参与金额与装箱。
- 接龙里的「人数」按单数算，不按人头——一个人点两份算两单，界面上写的是「单」。

### v15.1.0（2026-11-09）

让 AI 真的参与选号，而不是只在旁边写解说。

**怎么分工**

| 环节 | 谁做 | 为什么 |
|---|---|---|
| 挑号码 | AI（读完 120 期后自己决定） | 用户要的是「有机可循」，不是固定规则 |
| 写理由 | AI，每注一条 | 让人看得见它凭什么这么挑 |
| 校验号码 | 本地 | 范围、个数、重复、连号/大号段约束，错一注整票作废 |
| 算注数 / 覆盖 / 冷门度 / 成本 | 本地 | 这些是数学，不能让模型估 |

10 个出号的格子都能走 AI。撒网、复式、包蓝里 AI 只定「号码集合」，注数仍由覆盖算法、组合数、彩种规则给出。
回测和体检两格不出号，明确不让 AI 插手。

**喂给 AI 的东西**（一次约 5000 字符）

- 最近 120 期完整开奖记录（期号 + 主区 + 副区）
- 主区每个号的出现次数、当前遗漏
- 副区每个号的出现次数
- 和值中位数与 10%–90% 区间、奇数个数均值、三区均值、含连号期数占比、与上期重号均值
- 这一格的玩法要求 + 严格 JSON 输出格式 + 禁止「必出/稳中/精准预测」的硬性约束

**失败怎么处理**

1. 输出不是合法 JSON / 号码越界 / 个数不对 / 重复 → 把具体错误回给模型，重挑一次
2. 两次都不合规 → 退回本地算法，结果页顶部黄条写明「AI 这次没给出可用号码，下面是本地算的」
3. 超时（75 秒）/ 网络错误 → 同上，不抛异常、不白屏

**诚实边界**

- 结果页顶部标「AI 选号 · 模型名 · 耗时」，能看出这次是谁出的号
- 「AI 怎么想的」整段展示，不折叠
- 指标卡把「AI 的平均冷门度」和「本地算法同参数的平均冷门度」并排放，AI 更冷还是更不冷都照实说
- 每格底部真相条统一口径：AI 选号、本地算法、随手机选，中奖概率一样

**技术上**

- `aiChoose` / `parseAiPayload` / `buildPickPrompt` / `aiStats` 在 `lottery.js` 内，复用主应用注入的 `explain`（`aiPlain`），不新增网络端点
- 新增 `__ai` 测试导出，纯 node 环境可测解析与降级，无需真实 API
- 新增 `lottery_ai_test.js`（52 项）与 `lottery_ai_e2e.js`（32 项），后者用 Playwright 拦截 `/chat/completions` 验证真实页面流程

### v15.0.2（2026-11-09）

补上一件本来该说清楚的事：**这些号是哪来的**。

用户看着「胆拖缩水」会问两句：说锁死 2 个号，可我在哪锁？这 2 个号是谁定的，AI 还是随机？
问题出在文案——「锁死」听起来像「必出」，而界面从没交代过胆码的来路。

现在每一格结果顶部都有一块「号从哪来」，用一句话把规则摆出来：

- 胆拖：把 1–33 按「多少人会写这个号」排，第 1、2 名当胆。32、33 排最前，原因很土——大多数人写生日，日期最大 31。
  明确写「不是它们更可能出，是买它们的人更少」。
- 撒网：圈哪 12 个号是分区配额自动挑的（小号段 1 个、中段 4 个、大号段补满），不是按走势；号码定了注数是覆盖算法算的。

- 连号 / 复式：形状硬凑 + 最冷补齐 / 最冷 N 个做全组合。
- 回测 / 体检：不生成号码，只验算。

- 胆拖列表上方加图例：「下划线的是胆码，每一注都带着它；它不开出来，这 14 注全废。这不是『必出』，是『必须发生才有效』。」
